## React — My Core Expertise

React is where I spend most of my engineering energy. Here's a deeper look at what I bring to every React project:

### Architecture & Patterns
- **Component Design** — Building atomic, reusable, and composable components with clear separation of concerns
- **Custom Hooks** — Abstracting complex logic into clean, testable hooks (`useDebounce`, `useFetch`, `useIntersectionObserver`, etc.)
- **State Management** — Experienced with `useState`, `useReducer`, `useContext`, and integrating external stores
- **Code Splitting** — Leveraging `React.lazy` + `Suspense` for route-level and component-level splitting
- **Performance Optimization** — Profiling with React DevTools, applying `useMemo`, `useCallback`, and `memo` where they genuinely help

### Data & APIs
- Consuming **REST APIs** with Axios — handling loading, error, and success states cleanly
- Building **custom data-fetching hooks** to keep components lean and logic reusable
- Managing **async UI states** with skeleton loaders, optimistic updates, and graceful error boundaries

### Styling in React
- **Tailwind CSS** — utility-first, responsive, and theme-consistent UI at speed
- **SCSS Modules** — scoped styles, variables, and mixins for complex component-level styling
- **Dynamic class management** with `clsx` / `classnames` for conditional styling patterns

### Animation in React
- **GSAP + React** — integrating timeline animations with `useRef` and `useEffect` for scroll-triggered reveals, hero sequences, and page transitions
- **Three.js in React** — embedding 3D scenes using ref-managed canvases for immersive landing experiences

### Project Structure I Follow
```
src/
├── components/       # Reusable UI atoms & molecules
├── pages/            # Route-level page components
├── hooks/            # Custom React hooks
├── context/          # Global state via Context API
├── services/         # API calls & data layer
├── utils/            # Pure helper functions
└── assets/           # Images, fonts, icons
```

### Best Practices I Live By
- Write **self-documenting component names** — no guessing what `Card.jsx` does
- Keep components **small and focused** — if it scrolls, it should be split
- Always handle **loading + error + empty states** — not just the happy path
- Prefer **composition over prop drilling** — use children, render props, or context wisely
- Accessibility first — **semantic HTML**, `aria-*` attributes, and keyboard navigation
